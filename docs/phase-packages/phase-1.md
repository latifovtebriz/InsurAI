## 6. İzahlar (Azərbaycan dilində və C# Analoqları ilə)

### Nə etdik və Niyə belə etdik?
Sığorta sistemində AI agentlərini öyrətməzdən və ya qiymətləndirməzdən (evaluation) əvvəl sistemin "həqiqət etalonu" (ground truth) olmalıdır.
1. **Rule-Derived Labels (LLM ilə yox, qaydalarla yaradılan etiketlər):** Əgər etiketləri LLM-ə qoydursaq, model öz səhvlərini qiymətləndirə bilməz. Buna görə də hər bir sığorta hadisəsinin nəticəsi (təsdiq, imtina, insan yoxlaması, ödəniş məbləği, tətbiq olunan bəndlər) riyazi və hüquqi qaydalar əsasında müəyyən edildi.
2. **Effective Dating (Qüvvədə olma tarixləri):** Sığortada hadisə baş verən gün qüvvədə olan müqavilə şərtləri əsas götürülür. 2025-ci il qaydalarında bildiriş müddəti 3 gün və françiza 200 AZN olduğu halda, 2026-cı il qaydalarında bildiriş 2 gün və françiza 250 AZN-dir. Model köhnə hadisəni köhnə qaydalarla yoxlamalıdır.

### C# / .NET Analoqları:
- **Seed-Based Data Generation vs Bogus / AutoFixture:** C#-da integration testlər üçün `Bogus.Faker` istifadə edib saxta müştəri məlumatları generasiya edirik. Burada biz `random.Random(seed=42)` ilə eyni deterministik prinsipi tətbiq etdik.
- **Rules Catalog vs Business Rule Engines (Stateless / WorkflowCore):** `rules_catalog.py` C#-da `const` və ya `appsettings`-də saxlanan parametr kataloquna bənzəyir.
- **Effective Dating vs SQL Server Temporal Tables / EF Core Shadow Properties:** C# və EF Core-da `PeriodStart` və `PeriodEnd` ilə temporal cədvəllər qurduğumuz kimi, burada hər `ProductVersion` və `WordingClause` üçün `effective_from` və `effective_to` təyin etdik.
